# work-summary

## 做什么

将当前对话中实际开展的工作按完整需求归并，每项包含工作内容、结果、起止时间和预估工时。先说明本次新增、补充、修订或跳过哪些记录，展示草稿供你确认，再保存为每日 Markdown 文件。

当前提供中文版，调用名称为 `$work-summary`。按照[安装说明](../../../README.md#安装与切换语言)将完整技能文件夹复制到宿主技能目录，在新会话中调用。

## 使用示例

完成一个或多个需求后整理：

```text
$work-summary 总结这次对话完成的工作。
```

只整理指定需求，或补充对话中未体现的工作：

```text
$work-summary 只记录刚才完成的登录校验需求。
$work-summary 补充一项：协助排查设备连接问题，工时 1 小时。
```

看到草稿后可以调整、增加，再确认：

```text
第 1 项改成 1 小时，第 2 项还没有现场联调。
再加一项：部署测试环境，0.5 小时。
第 1 项今天 09:30 开始，11:00 完成；联调另行安排，本项只记录开发。
```

```text
确认保存。
```

也可以明确要求修改后直接保存：

```text
第 1 项工时改为 1 小时，按这个修改后直接保存。
```

后续修订时注明日期和条目，便于准确定位：

```text
$work-summary 把 2026-11-18 的 002 项总工时改为 4 小时。
$work-summary 给今天的 003 项补充异步发送改造，新增投入 1 小时。
```

## 文件在哪里

默认保存在用户主目录下的 `work-summary/yyyy-mm-dd.md`，例如 Windows 下的 `C:\Users\<用户名>\work-summary\2026-11-18.md`。多个项目使用同一个每日文件，每项注明项目。

可配置环境变量 `WORK_SUMMARY_DIR` 为统一的绝对路径，也可以在调用时指定目录。本次指定目录只对本次操作生效。使用远程或隔离的 Agent 时，需要将同一目录挂载为其可访问的路径；技能不会自行同步文件。

## 常见问题

- **一天可以调用多次吗？** 可以。先匹配当天已有记录；同一需求有新进展就补充原编号，没有新进展就跳过。当前对话的未保存草稿也会继续更新，不另生成相同工作项。
- **需求会拆得很散吗？** 默认一个完整需求对应一个工作项，方案、开发、排查、返工和验证放在内部；只有目标及交付结果独立、可以单独验收时才拆分。
- **怎么知道修改了什么？** 草稿先列变更清单；补充或修订展示新增工作、改变的字段及工时原值和新值，再给出完整内容。保存后返回受影响编号和变化摘要。
- **草稿里的编号会保存吗？** 草稿标题使用 `1 · 需求名称`；保存时根据当天记录分配 `001` 等正式编号，已有条目保留原编号。
- **起止时间从哪里来？** 使用你提供或已有明确证据支持的实际工作时间，允许只精确到日期；进行中填写“尚未结束”。缺失时间会集中询问，不根据聊天时间或当前时间猜测；你也可以明确同意暂时保留缺失标记。
- **工时是实际计时吗？** 是可调整的预估值。你提供的工时优先，未提供时根据已开展工作估算，不按起止时间差、聊天跨度或 Agent 运行时长计算。
- **未完成的需求能记录吗？** 可以，记录已经开展的工作和当前结果，并说明待完成内容。
- **不确认会保存吗？** 不会。未保存草稿保留在当前对话，跨会话需要提供草稿或重新整理。
- **能汇总其他会话吗？** 需要你提供相关内容，不能默认访问不可见会话。
- **会查所有历史记录判重吗？** 默认核对目标日期；你指定跨日需求或历史记录时，再读取相关日期。写入前会重新核对，出现影响已确认内容的变化时重新展示差异。
- **会登记到外部工时平台吗？** 本技能只维护本地 Markdown 文件。

## 如何判断执行符合预期

- 同一需求没有因技术模块或对话轮次被拆散，草稿中的范围、完成情况、起止时间和工时有依据。
- 新增、补充、修订和跳过的内容清楚可见，工时合计只包含本次变化。
- 确认后能在返回的文件路径查看记录，当天再次保存不会覆盖其他需求。
- 修订内容和工时更新原条目，新增投入与原有投入不会重复计算。
- 未保存、写入失败和已保存的状态说明清楚。
