# SSH

本文是 [英文执行规则](../../../skills/operations/ssh/SKILL.md) 的中文阅读版，供人阅读和维护，不作为技能入口。验证指定服务器的 SSH 访问，必要时指导用户自行配置公钥。

## 1. 适用范围

连接用户指定的服务器并验证访问。简洁报告连接结果，例如“SSH
连接成功”。如果用户已明确要求后续操作，则在验证成功后继续执行；如果用户仅要求验证连接，则报告结果后结束。不在回复中引用技能条款，也不以技能范围为由解释停止原因。

本技能仅包含说明。根据可用环境选择并执行原生 SSH 命令，不依赖配套脚本，也不创建连接包装脚本。

认证配置和验证始终使用用户本次指定的 IP。不替换为示例、上次连接或附近对话中的其他 IP。存在多个可能的目标 IP 时，先确认要连接哪一个。

## 2. 输入

- 必填：服务器 IPv4 或 IPv6 地址，以及用户为该目标确认的登录用户名。
- 可选：端口，默认 `22`；私钥路径。
- 复用用户为当前连接明确提供的值，不要求重复提供。
- 构造命令前校验 IP、用户名和端口；按实际本地 Shell 的规则引用参数，不将不可信文本直接拼接为 Shell 代码。

## 3. 前置确认用户名

生成任何针对目标服务器的连接、公钥安装或验证命令，以及尝试连接之前，先确认该 IP 对应的登录用户名。

- 用户在请求中明确提供了该目标的用户名，或已在当前对话中为同一目标确认过用户名时，直接复用，不重复询问。明确的 `user@IP`
  也视为已确认。
- 用户只提供 IP，且尚未为它确认用户名时，仅简短询问：`这台服务器 <server-ip> 的 SSH 登录用户名是什么？` 收到回答后再生成命令或连接。
- 不默认使用 `root`，不从本地账号推断远程用户名，不沿用其他服务器的用户名，也不轮流尝试常见用户名。此前使用猜测用户名发起的连接不算用户确认。
- 用户纠正用户名或说明用户名不同后，弃用旧值。实际用户名仍未知时先询问，随后所有命令，包括公钥安装命令，都统一使用确认后的值。

## 4. 识别运行环境

1. 确认操作系统、Shell 和可用执行工具。区分 Windows PowerShell、PowerShell 7、cmd、POSIX Shell、WSL 和容器，不仅凭操作系统推断
   Shell。
2. 使用适合当前环境的命令定位 SSH 客户端，例如 PowerShell 的 `Get-Command ssh`、cmd 的 `where ssh`、POSIX Shell 的
   `command -v ssh`。必要时检查客户端能力。
3. 使用当前环境的主目录、路径语法和引用规则。Windows、WSL 和容器中的密钥、SSH agent、配置及网络访问可能不同，不为绕过失败而擅自切换环境。
4. 缺少可用 SSH 客户端或执行工具时，说明缺失项，并给出适合该环境的下一步，不自动安装软件。

构造连接或公钥配置命令前，阅读 [references/commands.zh-CN.md](references/commands.zh-CN.md) 中当前本地与远端 Shell 对应的部分；只使用匹配环境的示例。

## 5. 执行连接

1. 复用已有 SSH 配置、ssh-agent 和默认身份。仅在用户指定密钥，或现有配置明确标识密钥时传入身份文件路径。不读取私钥内容。
2. 发起有超时限制的非交互连接。OpenSSH 使用 `BatchMode=yes`、`ConnectTimeout=10` 和 `ConnectionAttempts=1`。显式设置目标端口与
   `HostName`，避免 SSH 别名将指定 IP 重定向到其他服务器。验证时禁用本地命令和转发。
3. 执行最小远程命令，输出可识别的标记，并在支持时输出主机名和用户名。命令语法适配远端 Shell。只有 SSH
   退出码为零，且远程输出包含验证标记，才能报告成功。
4. 简洁报告连接结果；用户已要求后续操作时继续执行，否则报告后结束。仅在有助于识别连接时补充目标、用户名或端口。

SSH 执行后立即保存退出码，并检查实际输出中的验证标记；工具仅报告最后命令状态时，显式返回保存的 SSH
状态。远程命令语法错误不等于认证失败。首次主机密钥接纳需要交互时，给用户原生终端命令，不使用 `StrictHostKeyChecking=no`
绕过校验。验证仅使用短暂会话，不保留持久连接。

## 6. 处理首次认证与连接失败

检查失败时，先阅读 SSH 错误，再选择下一步：

- 超时、连接被拒绝或路由失败：报告连接问题，不归因于认证失败。
- 主机密钥变化：停止并说明不匹配，不删除 `known_hosts` 记录，不关闭主机密钥校验。
- 加密私钥需要口令：复用该密钥，让用户在自己的终端通过 `ssh-add` 解锁后重试，不替换为无口令密钥。
- 没有可用密钥导致认证失败：说明可能需要配置公钥，并提供下方“用户自行配置公钥”的手动步骤。不启动密码提示，不反复重试认证。

## 7. 用户自行配置公钥

提供适合用户本地操作系统、Shell 和远程账号的简短、可直接执行的命令。填入用户为当前目标提供的
IP、已确认的登录用户名、端口和适用路径。这些步骤由用户自行执行；不代替用户生成密钥、安装公钥或修改认证配置。

已有密钥对时，通常仅给两条命令：一条安装公钥，一条验证连接。仅在需要时补充生成密钥。只展示适合已识别环境且填入实际参数的命令。单条命令能够完成安装时，不要求用户显示并复制公钥、打开远程编辑器或单独执行权限命令。

1. 检查密钥文件是否存在，不读取私钥。复用现有密钥对，并明确说明无需重新生成。两个文件都不存在时，确保本地 SSH 目录存在，并给出交互式
   `ssh-keygen -t ed25519 -f <key-path>` 命令。不覆盖密钥；出现覆盖提示时，告诉用户回答 `n`。仅缺公钥时，提供 `ssh-keygen -y`
   ，并使用适合当前 Shell 的输出重定向恢复公钥。
2. 存在且适用时，优先使用一条 `ssh-copy-id` 命令。否则，对 POSIX
   远程账号，按 [references/commands.zh-CN.md](references/commands.zh-CN.md#一条命令安装公钥) 的示例将本地公钥通过管道传给
   SSH；远端目录创建、权限设置和安装包含在同一条命令内。不假设 Windows 自带 `ssh-copy-id`，也不对 Windows SSH 服务器套用
   POSIX 授权路径。
3. 简单管道会追加公钥，适用于首次配置，简短说明仅执行一次。密钥可能已安装，尤其存在授权选项时，不建议追加无限制的重复公钥；先检查授权情况，或给出适当的去重方法。不将普通首次配置变成长篇手动编辑流程。
4. 告诉用户在终端提示时输入服务器密码。不在聊天中索要凭据，不将凭据写入命令、环境变量或文件。
5. 附上同一目标的非交互验证命令。仅在相关时提示通过适用的 SSH agent 解锁加密密钥。

配置待完成时，如实说明连接尚未成功。用户确认完成后，再次执行连接验证。不能仅因其他已配置身份认证成功，就声称所选公钥已验证可用。

## 8. 操作边界

- 客户端支持时，连接验证可通过 `StrictHostKeyChecking=accept-new` 将新服务器主机密钥记录到 `known_hosts`。
- 私钥与凭据保留在本地，不打印、上传或复制私钥内容。
- 连接验证本身不修改 SSH 服务端设置，也不重启服务。验证成功后的其他远程操作仅在用户要求的范围内执行。
