# log-analysis

## 做什么

按服务、时间范围和关键词定位日志，在查询端筛选和统计，再按需读取原始事件，用可复核证据支持结论。调查保持只读。

## 什么时候使用

按[安装与切换语言](../../../README.md#安装与切换语言)选择中文或英文技能包，调用名称均为 `$log-analysis`。

通过 `$log-analysis` 显式调用，提供日志文件或可访问来源及调查目标。关键词可为空；时间、时区、服务与实例需要能够确定。

```text
$log-analysis
分析 ./api.log 中 2026-11-11 09:00 至 10:00（Asia/Shanghai）的错误及影响。
```

远程来源需要当前目标已通过用户显式调用的 `ssh` 验证。可在一次请求中同时指定两个技能：

```text
$ssh $log-analysis
连接 user@192.0.2.10，排查 api 服务最近一小时的超时。
```

来源为 Docker 时，Agent 读取所选语言包内的 `references/docker.md`，核对容器身份、挂载目录及日志留存。可查看 [Docker 中文规则](../../../skills/zh-CN/operations/log-analysis/references/docker.md)。

## 常见问题

- **会自动调用 ssh 吗？** 不会。目标尚未验证时提示用户显式调用；同一请求已指定两个技能时顺序执行，不额外确认。
- **只显示几条样本，统计是否也是样本？** 展示可以裁剪，统计必须覆盖完整选定范围；未完成采集时明确覆盖缺口。
- **查不到是否代表没有错误？** 只能说明在已核验范围内未发现，并注明留存、轮转、解析等限制。
- **会重启服务修复吗？** 日志调查本身只读，后续处理遵守用户已有授权。

## 如何判断执行符合预期

- 范围包含来源、服务、实例、绝对时间与时区，以及关键词匹配关系。
- 多行异常保留完整事件，不从展示样本外推总量。
- 结论区分事实和推断，关键证据可定位，覆盖缺口明确。
