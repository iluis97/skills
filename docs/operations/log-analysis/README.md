# log-analysis

## 做什么

根据日志排查服务问题：固定范围采集证据、提取现象、结合代码与近期变更定位具体原因，并按结论先行、证据可定位的方式总结。排查保持只读。当前提供[中文技能入口](../../../skills/zh-CN/operations/log-analysis/SKILL.md)，以及面向人的[命令速查表](commands-cheatsheet.md)（不进入技能执行，供手动查用）。

## 什么时候使用

通过 `$log-analysis` 显式调用，提供日志文件或可访问的日志来源及调查目标；时间、服务与来源需要能够确定。

```text
$log-analysis
分析 ./api.log 中 2026-11-11 09:00 至 10:00（Asia/Shanghai）的错误及影响。
```

来源为 Docker 时，Agent 会读取包内 `references/docker.md` 核对容器身份与日志留存。

## 常见问题

- **会预设排查方向吗？** 不会。按证据从现象往回推，依赖、配置、资源、数据、代码等因素同等对待；只有首次出错时间贴近部署或错误签名是新出现时，才比对近期变更。
- **查不到是否代表没有错误？** 只能说明在已核验范围内未发现，覆盖缺口会在结论中如实说明。
- **会直接修复问题吗？** 排查只读，不改配置、不重启服务；结论只给处理方向，处理动作由你授权。

## 如何判断执行符合预期

- 范围包含服务、实例、绝对时间窗与时区，覆盖缺口如实说明。
- 根因有证据链：现象、代码位置、变更节点（如涉及）可逐一复核，不凭单条日志或猜测下结论。
- 结论区分事实、推断和未验证事项，与近期变更无关时有反证支撑。

## 专属维护要求

- 技能只保留必要的问题定位与总结指导，不追加假设族清单或穷举式排查步骤，避免约束 Agent 的现场推理。
- 来源相关的具体规则（如 Docker）放包内 `references/`，按需读取；调整定位或总结要求时同步技能入口与本说明。
