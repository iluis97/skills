# restate-goal

## 做什么

用自己的话复述用户的目标、要解决的问题和满足目标的最小改动，把理解摊开供确认，避免方向跑偏或自行放大方案后大量返工。只做复述与对齐，不展开方案、不开始实现。当前提供[中文技能入口](../../../skills/zh-CN/workflow/restate-goal/SKILL.md)。

## 什么时候使用

通过 `$restate-goal` 显式调用，通常在以下时机：

- 大任务开工前，先确认对目标的理解；
- 对话进行到中途，感觉方向开始偏离；
- 需求描述含糊、存在多种解读时；
- 换会话或清空上下文后，需要验证理解是否延续正确。

```text
$restate-goal
```

调用后 Agent 会输出目标、问题、最小改动、依据和待确认项，等待你确认或纠正。

## 常见问题

- **复述完会自动开始干活吗？** 不会，未确认前不进入实现；但如果你在同一请求里已授权直接执行，它会按授权推进。
- **复述和复读原文有什么区别？** 复述要求用自己的话概括目标与问题，原文改写不算复述。
- **它会不会把猜测当成我的需求？** 推断部分会单独标出并列入待确认，不混进“目标”里。
- **为什么要复述最小改动？** 用来发现复述后自行放大的范围。最小改动只说明满足目标的最小范围，不替代方案设计，也不限制你明确要求的完整实现。
- **和 `/plan` 有什么不同？** `/plan` 讲“怎么做”，本技能讲“我认为你要什么”，在流程上更靠前。

## 如何判断执行符合预期

- 目标写得是最终结果，而不是用户提到的动作或方案。
- 事实与推断分开，推断有依据，歧义点被明确列出。
- 最小改动没有扩大目标、范围或授权，并说明了它与目标的对应关系。
- 篇幅简短，只到“能判断理解是否一致”的程度。

## 专属维护要求

- 保持单一职责：只做目标、问题与最小改动的复述对齐，不扩展成需求分析、方案设计或任务拆解。
- 调整输出字段或复述要求时，同步技能入口与本说明，保持两处一致。
