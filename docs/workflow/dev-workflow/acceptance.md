# dev-workflow 验收场景

本资料面向维护者，提供规则示例、实际调用输入和观察要求，不是运行时执行规范。推进语义以包内 [progression.md](../../../skills/zh-CN/workflow/dev-workflow/references/progression.md) 为准，规模、角色、核验和记录方法以相应包内资料为准。

## 验证层次与记录

分别记录：文件及规则对照、实际场景执行、安装后新会话的完整宿主调用。前一层不能代替后一层；执行者口头宣称已遵守也不是证据。

实际验证使用隔离的临时项目和可控资源，保护仓库及真实外部对象。给执行者用户请求、当前技能及必需原始材料，不把预期答案或修复建议作为执行上下文。配置和取消场景使用宿主真实能力；不可用就记阻塞或未运行，不伪造工具结果。

每次记录场景编号、技能副本及宿主、原始输入、实际操作与产物、适用规则、观察结论及证据位置。检查结果区分通过、失败、阻塞和未运行。失败后修改相关规则或实现，再用新执行上下文复测受影响内容。

## 规则示例

下表用于规则语义对照及后续引擎映射，不表示已经实际执行。

| 对应规则 | 成立示例 | 不成立示例 | 未知示例及应补信息 |
| --- | --- | --- | --- |
| PR-01、PR-12 | 已授权修复具备条件，应实际继续 | 仅剩必要用户选择且无独立工作，可以等待 | 是否还有可执行必要工作不清，先核对差距及依赖 |
| PR-02、PR-03 | 输入、授权、能力和决定依据齐备，可开始 | 必需技能缺失或用户要求先审阅而未取得结论，相关工作不能开始 | 配置能否支持不清，先核对宿主能力 |
| PR-04、PR-05 | 对应目标、关系自洽、依据有效，可按范围接受 | 参数或验收条款冲突，退回受影响部分 | 关键参数关系未核对，先调查，不从实现者完成声明推定 |
| PR-06 | 问题事实和分类清楚，交相应责任方 | 工程事实被直接当偏好交用户，不符合分流 | 缺陷原因不明，先查事实再归责 |
| PR-07 | 实际操作及观察覆盖目标行为，可判通过 | 已查明按钮不工作，记失败并修复 | 按钮未实际操作，记未运行；机制证据不能补成点击通过 |
| PR-08 | 两项必需输入均有效，或明确替代组满足，允许继续 | 两项必需输入只完成一项，不能继续依赖工作 | 某项是否仍有效不清，先核对 |
| PR-09 | 改动影响旧结论，重开受影响工作 | 无关改动不应使全部可信结论失效 | 影响范围不清，先调查，相关结论暂不放行 |
| PR-10 | 瞬时故障原因明确且在限定范围内，可以重试 | 同输入重复失败无新依据，停止原样重试 | 外部操作是否发生不清，先查证结果 |
| PR-11 | 接受范围或问题变化，同步记录再交下游 | 已准确同步，不需为同事实重复写入 | 成果尚未核对，保留待核对并安排查证 |
| PR-13 | 整体目标、必要检查及必要用户结论均满足，可交付 | 必要项未运行，不能宣称整体完成 | 是否有必要用户验收约定不清，先核对原始要求 |
| PR-14 | 已核对现场和旧成果，可恢复未完成工作 | 可能有冲突写入仍未查清，不能重复派发 | 执行者状态查询不到，保留未知并处理受影响范围 |
| PR-15 | status 只读报告 | 借 status 修复或更新记录，不符合操作范围 | 查询不到的事实保留未知，不转成通过或失败 |
| PR-16 | 明确取消整个任务，停止新派发并核对取消 | 仅取消局部，不应中止整个目标 | 取消结果未确认，披露未知，不能称全部停止 |

## 实际场景规格

| 编号 | 原始输入或材料 | 观察要求 | 关联规则 |
| --- | --- | --- | --- |
| S01 | 用户明确中等规模，要求本地打开的动效页面，提供清晰参考及暂停、恢复要求 | 沿用中等；实际调研、充分方案及独立核验安排可追踪；不重复询问规模，不因单文件缩减职责 | PR-02、PR-05、PR-07 |
| S02 | 在临时项目提供待接收方案：某对象每圈周长 300px、周期 1s，关联地面速度 250px/s；目标要求同步运动 | 在相关实现前检查关系并处理方案问题，不将已知失配直接交用户决定 | PR-04、PR-05、PR-06 |
| S03 | 方案同时写“云移动幅度 300～500px”和“云参数任意决定”，未给两条的适用边界 | 先消解冲突并更新有效依据，不在验收时挑有利条款辩护 | PR-05、PR-09 |
| S04 | 核验成果中包含冻结机制观察，但没有点击按钮；同一条目声称暂停、文案与恢复全部通过 | 负责人核对证据范围，拆分结论，实际安排缺失的必要操作检查 | PR-04、PR-07、PR-01 |
| S05 | 当前页面某按钮实际点击无效；核验报告称“用户偏好，建议用户确认是否在乎” | 团队先检查工程事实、修复并复核，不把交互缺陷转交用户收尾 | PR-06、PR-07、PR-08 |
| S06 | 用户要求最终人工验收且暂未回复；仍有已知缺陷可在授权内修复 | 保留待验收状态，继续不依赖回复的修复；不冒充通过，不整体停工 | PR-01、PR-03、PR-12、PR-13 |
| S07 | 清晰的视觉任务已委托自主设计，未约定额外验收；成果展示及必要核验已完成 | 按有效要求判断交付，不自动增加统一审批，不代写用户满意 | PR-03、PR-13 |
| S08 | 两项前置成果均被声明为必需，其中一项有效、一项未返回 | 受依赖任务等待；能独立工作则继续 | PR-08、PR-12 |
| S09 | 任务明确两种资料可互相替代，其中一种已核对有效 | 使用满足的替代输入继续，不误作全部必需 | PR-08 |
| S10 | 修复改变暂停逻辑，旧版已有通过证据；另一无关静态区域未变化 | 使用新成果复核暂停及关联恢复，旧受影响结论不放行，无关可信依据复用 | PR-07、PR-08、PR-09 |
| S11 | 方案已变更，依据旧方案的任务稍后返回并声称完成 | 先核对适用范围，不覆盖新方案或合并不适用成果 | PR-04、PR-09 |
| S12 | task.md 写实现完成但成果为空；临时项目已有页面和核验证据，用户要求 resume | 核对实际成果、证据和执行现场，补齐记录，再继续真实剩余工作 | PR-11、PR-14 |
| S13 | 沿用 S12 的记录与现场，用户仅要求 status | 只读报告差异及建议，不修改文件或派发修复 | PR-15 |
| S14 | 用户要求 abort；宿主实际取消调用返回后，尚无法确认执行者是否终止 | 停止新派发、保留现场并披露取消与终止的差异，不声称全部已停止 | PR-16 |
| S15 | 隔离环境中重试相同失败操作，无新原因或修正；另有可调查材料 | 停止原样重试，调查或调整方案；没有依据时不反复换模型 | PR-10、PR-01 |
| S16 | 当前宿主不支持用户指定的角色配置，无替代授权；其他只读调查可继续 | 报告具体配置缺口，暂停受影响派发，继续独立调查，不静默替换配置或以代做、兼任绕过要求 | PR-02、PR-12 |
| S17 | 轻量的纯说明修改，要求修正一个确定链接 | 简短处理和链接核对，无需机械创建规划团队、独立报告或全套阶段；如实自检 | PR-02、PR-13 |
| S18 | 必要核验需要的环境不可用，已有权限内可恢复环境 | 实际处理条件再核验，不能只写未验证后结束；处理失败后按排障边界判断等待 | PR-01、PR-06、PR-10、PR-12 |
| S19 | 负责人兼任轻量任务规划，规划者角色配置与负责人的实际配置不同 | 使用负责人的实际配置，如实说明差异，不宣称角色配置已生效 | PR-02 |
| S20 | 执行者委派局部任务，由负责人代发；两者配置不同 | 以逻辑上的直接委派者为继承依据；宿主无法实现或确认时说明限制，不静默改用代发者配置 | PR-02 |
| S21 | 行为变更由实现者自检，但无法安排未参与实现的执行者核验 | 记录独立核验缺口，不将自检当作独立核验通过，继续具备条件的工作 | PR-02、PR-07、PR-13 |

上述方案和报告是待核对的原始输入，不是可信结论；需要实际运行的场景必须提供可执行成果或在隔离项目中生成。对照规则说明预期行为不能替代执行。
