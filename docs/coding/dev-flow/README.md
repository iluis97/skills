# dev-flow

## 做什么

以可校验、可恢复的阶段流程完成需求确认、设计、实现、独立审查、测试、知识沉淀和总结。small 任务由主线程完成，medium/large 任务按角色派发。

## 如何使用

当前提供[中文技能包](../../../skills/zh-CN/coding/dev-flow/SKILL.md)，尚无英文版本。按[安装与切换语言](../../../README.md#安装与切换语言)复制完整技能文件夹，在新会话显式调用：

```text
$dev-flow start 实现订单查询接口
$dev-flow status order-query
$dev-flow resume order-query
$dev-flow abort order-query
```

阶段开始默认只播报一行，例如：

```text
[TASK-02] architect · Agent a81f（worker） · 模型：继承（未知） · 推理：high（已提交）
```

普通进度不重复身份信息；重试或降级补充一句。最终回复聚焦交付与验证，需要了解具体执行情况时可直接询问“当前谁在执行，用了什么模型和推理等级”，或使用 `status` 查询。

## 常见问题

- **为什么模型显示继承或未知？** 默认不绑定供应商模型，且部分宿主只返回 Agent 句柄。未得到宿主回报时不能确定具体型号。
- **“已提交”和“已确认”有什么区别？** 前者有本次真实调用参数作为依据，后者还有宿主对该字段的明确回报；模型和推理等级分别判断。
- **角色是不是具体 Agent 类型？** `architect` 等表示业务职责；宿主 Agent 类型和真实句柄另外记录，主线程执行会明确标注。
- **如何查看降级或之前的尝试？** 询问执行历史，主线程按需读取 `status --details`。记录保存在任务的 `workflow-state.json` 中。
- **修改仓库后会立即改变已有会话吗？** 仓库源码和安装副本独立，需另行同步所需副本，并在新会话验证实际效果。

## 如何判断符合预期

- 每个阶段启动一行即可看出角色、执行方式、模型与推理等级的确认依据。
- 重试、参数调整和内联降级可见，具体请求及宿主证据可追溯，未知值没有被猜测补全。
- TASK-01/SOLO 如实标注主线程，角色配置不会被当成主线程已经切换配置。
- 阶段完成前有实际校验，未运行项、失败和风险会明确说明，最终答复不附冗长执行日志。

详细执行约定位于技能包内的[执行记录与简洁播报](../../../skills/zh-CN/coding/dev-flow/references/execution-reporting.md)。文件核对和脚本测试不能证明宿主真实调用效果，需在新会话分别观察正常派发、无配置回报和降级重试。
