# add-doc

## 做什么

完善代码文档与注释，说明意图、契约、限制及不直观的逻辑。仅修改文档和注释，保持可执行代码与接口行为不变。

## 什么时候使用

通过 `$add-doc` 显式调用。未指定文件时，检查暂存、未暂存及未被 Git 忽略的未跟踪代码文件，只处理这些变更涉及的声明和逻辑。

```text
$add-doc
检查本次未提交变更，补充必要的文档和注释。
```

也可以指定文件，技能将在这些文件内检查，不再限于未提交代码。

## 常见问题

- **没有未提交变更怎么办？** 报告没有可处理内容；可以重新调用并指定已有文件。
- **会重构代码吗？** 只处理文档和注释。发现行为问题时可以说明，不扩大修改范围。
- **Java 注释放在哪里？** Javadoc 放在声明整个注解块上方，不能插在注解之间。

## 如何判断执行符合预期

- 差异仅涉及目标范围内的文档和注释，保留已有用户修改。
- 注释符合实际行为，沿用项目语言与格式，不逐行翻译代码。
- 报告修改内容及适用检查的结果。
