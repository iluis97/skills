# code-like-me

## 目标

像我一样思考和组织代码：职责清晰、命名直观、复用现有抽象与工具，保持代码易读、易改、易扩展。

按用户要求完成实现与必要验证；仅要求分析或建议时，按该范围输出。

## 1. 规则优先级与适用范围

- 优先级：任务明确要求 → 项目规范 → 同模块维护良好的相邻实现 → 本技能偏好。始终保证正确性与接口兼容性。
- 通用规则适用于各语言，按其惯用方式实现；语言专节仅在使用对应语言时叠加应用，未列出的语言以项目规范为准。
- 已有项目延续局部约定；新增模块按需求设计，不照搬参考项目的包名、框架或业务模型。
- 个人习惯以多个一致实现为依据，不从单个特例、生成代码或其他作者代码推断。质量规则是约束，不代表历史代码全部满足。
- 保留用户已有改动，仅修改任务所需文件；不为统一风格扩大范围、格式化整个项目、升级依赖或重构无关模块。

## 2. 执行流程

1. **明确边界**：识别需求、接口、兼容要求和已有改动；仅在缺失信息影响业务行为且上下文无法判断时提问。
2. **阅读上下文**：检查项目说明、构建与语言版本、目录、相关调用方、实现和测试；若同模块存在类似实现，选取两到三个确认与任务相关的约定，阅读范围与改动相称。语法与 API 必须兼容目标版本。
3. **选择实现**：先复用类型、接口和工具，再考虑新增抽象；复杂流程梳理稳定步骤与变化点，简单需求直接实现。
4. **完成修改**：按职责组织逻辑，方法或函数保持短小、语义完整，同时实现边界校验与失败处理。
5. **验证与审查**：按影响选择编译、静态检查、现有或针对性新增测试，重点覆盖分支、状态与边界；按文末清单审查差异并交付。

## 3. 通用编码规则

### 设计原则与模式

- **职责与契约**：运用 SOLID 与迪米特法则，保持职责清晰、接口精简、低耦合。不额外收紧接口输入条件或暗改返回、异常、副作用语义；受容器管理的依赖沿用项目注入方式。
- **复用与抽象**：优先已有组件与扩展机制、组合和委托；继承用于真实替换关系或稳定模板流程。仅为明确的变化点、扩展或隔离需求引入模式与抽象，简单逻辑保持直接，避免维护成本超过收益的层级。
- **组件协作**：复杂流程检查依赖方向、资源所有权、生命周期、顺序、并发与失败传播；验证替换和扩展不破坏契约。

### 命名与逻辑组织

- 类型、方法、函数、变量表达业务概念与用途，沿用项目英文命名、缩写和类型后缀。
- 方法或函数名体现动作与对象；布尔命名沿用项目惯例。区分查询、转换、校验与执行，名称不得隐藏写入或外部调用。
- 主流程呈现步骤，判断与转换提取为语义明确的方法或函数；保留连贯局部逻辑，避免大量仅包装一行表达式的调用。
- 前置校验、无操作和失败分支可提前返回以减少嵌套，返回行为须符合契约。
- 重复业务规则归入所属领域或服务；跨业务通用且无状态的能力才放入工具模块。
- 用常量、枚举或语言惯用类型表达有意义的固定值，不机械提取仅出现一次且语义清楚的字面量。

### 数据与状态建模

- 数据对象承载数据与必要局部行为，服务负责业务编排；实体与对外契约遵循分层约定。
- 有限稳定的类型、状态和操作集中建模，减少散落值与重复分支；复用的编码查找、描述获取和判断归入所属类型或转换组件。
- 明确空值与未知编码的返回、默认或异常契约，不擅自视为正常状态；接口、持久化与消息使用稳定编码，不随意修改已发布编码。
- 状态类型封装自身属性相关的简单行为；服务依赖、数据库或外部调用等复杂行为归入策略或业务组件。

### 校验、异常与日志

- 入口校验格式与必填项，服务校验存在性、权限、状态与业务约束，沿用既有边界，避免重复。
- 复用校验工具、业务异常与错误码；消息说明业务原因，不向调用方暴露堆栈或底层细节。
- 仅在可恢复、补充上下文或转换异常语义时捕获，其余沿用统一处理；不以空集合、空值或成功结果吞掉失败，允许缺失按契约处理。
- 沿用日志框架与级别，用参数化日志记录关键变化、外部失败和排查上下文，避免无意义高频输出。
- 高频路径保留业务标识；日志涉及序列化或较重计算时先检查级别。异常不重复记录，当前层需记录时保留堆栈；不输出凭据、令牌或完整敏感对象。

### 集合、转换与数据访问

- 优先现有集合、字符串、转换与数据访问工具；标准库足够时不新增依赖。
- 过滤、映射、分组使用清晰的语言惯用写法；复杂分支、副作用或提前结束优先用循环。
- 明确空集合、空元素、重复键与顺序语义；合并数据时按业务定义冲突策略，不随意保留一条。
- 明确数值默认值、精度、舍入与比较语义，不依赖工具隐含行为，不无依据地将零视为缺失。
- 沿用对象转换与字段映射方式，核对必填、类型与含义，避免通用复制掩盖差异。
- 复用数据访问组件或服务查询，避免循环逐条查询；批量操作考虑批次与事务语义。
- 事务按业务原子性划定，遵守框架事务与回滚规则；外部调用、缓存、消息的失败补偿沿用既有机制。
- 写库后维护缓存时，核对并复用提交后回调机制，避免回滚后缓存已变化；明确无事务与回调失败的处理。
- 重复且可可靠失效的热点中间结果可缓存；优先现有组件，明确键、生命周期、写后失效与并发语义，不照搬容量或 TTL。
- 更新、删除与批处理明确范围和重复执行行为，保留必要条件、返回值检查与并发控制。

### 注释与格式

- 沿用缩进、导入、换行、声明标记排列及注释语言，使用现有格式工具。
- 类引用通过 import 引入，不在代码中使用全路径类名；仅当存在同名类冲突或导入会产生歧义时，才在使用处写全路径，并保持局部写法一致。
- 中文业务注释说明意图、约束、算法步骤与取舍，不逐行翻译；公共能力、复杂方法或函数与关键字段按项目要求描述实际参数、返回与异常。
- 文档注释放在语言和文档工具要求的位置，局部说明靠近实现；行为变更同步更新注释，不编造作者、日期、性能保证或未实现能力。

## 4. 各语言的补充规则

### Java

以下规则仅应用于 Java；Lombok、MyBatis-Plus 等规则仅在项目已使用对应依赖时生效。

#### Lombok 与对象建模

- 用 Lombok 简化普通 Bean、请求/响应、配置对象与枚举；按需选择 getter、setter、构造器、builder 和日志注解。
- 可变 Bean 沿用 `@Data` 风格，只读对象仅开放读取；确认生成的 `equals`、`hashCode`、`toString` 合适，继承、实体关联或敏感字段需显式控制，避免递归或泄露。
- 构造器注解满足框架实例化要求；`@Builder` 仅在改善构建可读性时使用，不替代必填校验或默认用于所有类。
- 注入方式沿用目标模块；无约定且使用 Lombok 时可用 `@RequiredArgsConstructor` 配合 `private final`，不批量替换存量代码。
- 简单稳定的响应转换可用 `static of(...)` 显式逐字段映射；已有统一转换组件时优先沿用。
- 复用实体公共基类字段与表映射约定；使用 `@EqualsAndHashCode(callSuper = true)` 前确认父类字段应参与相等性判断，不统一套用。

#### 枚举

- 枚举的编码与描述存入由构造器初始化的字段；对外编码禁止使用 `ordinal()`。
- 使用 Lombok 时，可用 `@Getter`、`@AllArgsConstructor` 与 `private final` 属性；命名、编码类型、字典注解沿用项目，不强制 `Enum` 后缀、`Integer` 或构造器注解。

#### 集合、数值与数据访问

- Stream 用于清晰的过滤、映射、分组；简单可空转换可用 `Optional`，复用的转换可传入 `Function`，保持直观。
- 按业务使用 `BigDecimal`，数值比较用 `compareTo`，需同时比较数值与标度才用 `equals`。
- `Collectors.toMap` 未提供合并函数时遇到重复键会抛出异常；业务允许重复键时，提供实现业务冲突策略的合并函数。
- 已使用 MyBatis-Plus 时，可用 `LambdaQueryWrapper` 和 getter 方法引用。
- 使用代理式事务时，确认调用经过代理，且配置的回滚规则覆盖预期异常类型。

#### Javadoc

- 类、方法、构造器与字段的 Javadoc 放在声明整个注解块上方；无注解时直接放在声明上方，不插在注解之间或注解与声明之间。

- [ ] 差异满足任务范围与适用约定，没有意外改变行为或覆盖用户改动。
- [ ] 验证覆盖受影响的契约、边界与失败路径，注释与最终实现一致。

交付时简述修改、验证结果，以及未执行或受阻的相关检查；仅解释影响使用或维护的关键取舍，不复述技能规则。
