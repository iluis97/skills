# add-doc

## 1. 范围与约束

- 未指定文件时，检查已暂存、未暂存的代码变更，以及未被 Git 忽略规则排除的未跟踪代码文件。仅修改这些变更涉及的声明与逻辑的文档。
- 指定文件时，仅审查这些文件内的文档；修改不必局限于未提交的代码。
- 跳过已删除的文件。没有适用的代码变更或现存目标文件时，说明无可处理内容并结束。非 Git 仓库环境且未指定文件时，请求提供目标文件。
- 保留用户现有改动。仅修改文档与注释，不改变可执行代码、接口行为或无关文件。

## 2. 执行流程

1. 按上述规则确定待处理范围。
2. 阅读相关代码与上下文，理解实际行为及项目文档约定。
3. 按下述指南添加或更新文档。
4. 审查差异，核对准确性、位置与范围；按改动需要使用可用的文档检查，确保没有无关修改。

## 3. 撰写指南

- 优先更新现有文档，避免重复创建。
- 说明意图、契约、约束与不直观的逻辑。参数、返回值与异常的说明应提供名称和类型之外的信息。
- 遵循项目既有的语言、注释风格及文档格式。
- 将文档注释放在语言与文档工具能够关联到预期声明的位置；在目标范围内纠正错位注释，实现逻辑的注释应靠近所解释的代码。
- 不臆造行为，不添加仅复述代码的注释。

## 4. Java Javadoc 位置

- 类、方法、构造器或字段的 Javadoc 紧邻声明的整个注解块上方；无注解时，直接放在声明上方。不插在注解之间或注解与声明之间。

```java
/**
 * 返回用户的显示名称。
 */
@Override
@Nullable
public String getDisplayName() {
    return displayName;
}
```

## 5. 交付

简述修改的文件、完善的文档，以及已执行的检查和结果。如有相关检查无法执行，应如实说明。
