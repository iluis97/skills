# Go 编码规则

仅当目标仓库主语言为 Go 时加载。项目已有规范优先。

## 格式与导入

- 使用 `gofmt` 和 `goimports`。
- import 分组为标准库、内部包、第三方包，并按字母排序。
- 导出名称必须有文档注释，格式为 `// 名称 描述`。

## 错误处理

- error 作为最后一个返回值，必须处理或明确忽略。
- 使用 `errors.New` 或 `fmt.Errorf("%w")` 保留错误链。
- 一般业务错误不使用 panic；不变量断言可以使用，导出方法使用 `MustXxx` 命名。
- `recover` 只在 defer 中使用，并有明确边界。

## 命名与结构

- 包名小写、简短，与目录一致。
- 文件名使用小写下划线。
- 特有名词沿用 Go 惯例，如 `APIClient`、`repoID`。
- 文件名和函数行数遵循项目约定；无约定时优先保持职责完整和可读。

## 控制与资源

- `range` 只使用一个值时用 `_` 丢弃另一个。
- `switch` 按项目约定处理 default。
- 优先清晰返回；禁止 goto。
- `defer` 紧跟资源创建和判错，避免在循环中累积。
- 嵌套过深时先拆分职责完整的逻辑，不机械提取转发函数。

## 测试

- 测试文件使用 `_test.go`。
- 测试函数使用 `TestXxx`，必要时使用 `Test_Foo` 或 `TestBar_Foo`。
- 优先使用表驱动测试和 `t.Run`。

## 依赖

- 使用 Go Modules。
- `go.mod` 和 `go.sum` 保持同步。
