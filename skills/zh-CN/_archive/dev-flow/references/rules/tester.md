# 测试规则

## T1 按风险选择层级

函数和边界用单元测试；模块、数据访问和 API 契约用集成/API 测试；关键用户旅程用 E2E。使用能覆盖风险的最窄层级。

## T2 沿用项目体系

使用已有框架、目录、fixture、helper、命名和 runner。不为流程形式引入新框架或重型依赖。

## T3 职责边界

只修改测试和测试支持文件。生产缺陷返回 developer，不在测试阶段修补生产代码。

## T4 真实执行

先跑最窄测试，再按项目要求扩展。严格记录 passed、failed、blocked、not-run。静态检查不能替代集成或 E2E。

## T5 可重复与安全

测试数据隔离并在适用时清理。凭据和环境地址只从既有配置或环境变量获取。

## T6 完成门禁

必需测试失败或关键验证阻塞时不得标记 completed。无法运行的外部依赖场景必须说明条件、替代检查和剩余风险。

测试结果写入 `stage-result.json`，完成后运行 `workflow.py validate`；不得修改 `workflow-state.json`。
