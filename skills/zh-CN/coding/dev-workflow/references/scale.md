# 需求规模判断

规模用于确定实际工作深度与组织投入；开始、交接和完成的判断统一适用 [progression.md](progression.md) PR-02、PR-05、PR-07、PR-13。

## 判断与使用

“小型／轻量”对应轻量，“中等／常规”对应常规，“大型／复杂”对应复杂。用户已明确说明时直接采用并记录来源；未说明时，负责人根据原始需求、已有上下文和适量阅读判断，写一两句理由，不要求用户选档。

规划者及其他执行者提供影响面、依赖、风险和验证成本等事实与调整建议，由负责人综合决定，不自行定档。无需等待完整调研才初判，不单独建立规模分析任务或报告。

| 规模 | 判断依据 | 工作基线 |
| --- | --- | --- |
| 轻量 | 目标明确、影响局部、实现路径清楚、验证直接 | 查明直接影响的事实；简短说明做法及完成依据；主线程可规划，通常不拆子任务；行为变更仍需独立核验 |
| 常规 | 需要调研，有关联变更、局部取舍或一定验证成本 | 查清相关实现、依赖和约束；形成目标、方案、关键关系、实施安排及验收方法；默认独立规划；核验主要行为、整合与必要体验 |
| 复杂 | 目标或技术路径不确定，跨模块依赖多，取舍、风险或验证成本较高 | 在常规基础上调查跨模块影响，按需要比较方案或先做试验；明确依赖并分批交付；核验跨模块、异常及相关恢复行为 |

常规和复杂任务已有充分方案时可复用，负责人记录来源及复核依据；这不等于取消规划职责。方案是否充分依据 PR-05 判断，用户认同按 PR-19 核对，已有同一方案的有效认同不重复索取。所有规模均适用 PR-19；轻量方案可以是几句话，不要求独立设计文档。独立执行能力缺失按 PR-02 处理，不静默改成主线程自检通过。

常规及复杂任务使用稳定目标标识关联完成条件、方案选择、成果及证据，形式可为现有记录中的简短表格。每项必要目标应能找到验证方法和当前结论；核验仍回看原始要求，主动发现清单遗漏。方案、证据可引用独立文件，不重复抄录。

规模落实要记录实际安排，例如“用户明确中等；规划者查明现有实现并提交方案，未参与实现的核验者检查交互与动态表现”。只记“常规”不足以说明组织要求已经落实。不强制固定人数或文件数量，精简产物仍须完成相应工作。

综合考虑：

- 用户希望得到的结果是否明确，是否存在需要用户选择的目标差异。
- 影响是否跨模块或涉及公开契约、数据、权限、运行环境等重要边界。
- 能否直接复用已有实现，是否需要调查和比较技术路径。
- 工作之间的依赖、可并行性和整合成本。
- 要证明目标达成，需要哪些真实环境、工具、交互或人工体验判断。

文件数量仅是线索；单文件可能涉及复杂动效或重要契约，大量机械变更也未必需要复杂组织。

## 动态调整

负责人把规模来源、实际组织安排及后续调整原因写入唯一任务记录。新发现使任务变复杂时增加必要调研、分工或验证，变简单时合并不必要工作；保留已有成果，不清空记录或重启整套流程。

调整规模或组织投入时说明查证依据和影响；用户已明确规模时，不因单文件、实现容易或减少开销静默下调其投入要求。涉及用户范围或取舍时适用 PR-03，普通组织调整不新增审批。

例如“改一个页面”若涉及整体观感、动效联动及交互，不能因单文件就判轻量；“调整多个文件的同一说明”若规则明确且无行为变化，也不因文件多就机械拆团队。

规模变化不意味着获得扩大任务范围、访问权限或额外外部写操作的授权。
