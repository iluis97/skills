# 子 Agent 委派方法

选定子 Agent 时由实际派发者读取。本文件说明宿主操作方法，选择与切换以 [progression.md](progression.md) PR-17 为准，任务准备和资料交接见 [tasks-and-delegation.md](tasks-and-delegation.md)。

## 派发与配置

使用宿主提供的子 Agent 创建接口，先核对真实 schema、并发限制、上下文及配置覆盖规则。主角色配置按 [roles.md](roles.md) 解析；具体值在接口支持且允许时提交，`inherit` 不作为字面参数传入。无法满足覆盖或上下文要求时按 PR-02 处理，不伪造继承成功。

任务消息提供目标、输入、边界、完成条件和相关资料。传递必要上下文；选择全量继承或隔离上下文时以实际配置约束和任务需要为依据。写入任务明确文件所有权，说明其他执行者可能同时工作，保留已有修改。

宿主返回真实执行者后关联 Agent ID、角色、任务、逻辑委派者及配置依据。标识返回仅证明创建调用已有结果，实际开始及配置生效仍按宿主回报分别判断。

## 接回与继续

使用宿主已有的消息、等待、查询和继续任务接口。返回通知后核对实际成果与依据，按 PR-04 接收，再反馈具体缺项或继续原任务；不为每次修复新建执行者。区分只发消息、启动空闲执行者和中断当前执行的接口语义，不假定消息已经应用。

有其他必要独立工作时继续；需要等待时使用合理等待或有界查询，不密集空转。消息、句柄或执行者完成自述都不能替代独立核验及目标判断。

规划由子 Agent 承担时，负责人向用户展示当前方案、主动通知验收并承接讨论，将调整交回原规划者；修订后按 PR-05 检查。用户在主对话明确认可后，由负责人按 PR-19 核对并记录，再派发相关实施。子 Agent 返回方案或负责人内部采纳不代表用户验收通过。

## 恢复、切换与中止

恢复先查询已有 Agent ID，核对仍运行的写入者及已返回成果。用户要求切换 thread 时先满足 PR-17 的交接条件，沿用有效成果，不让新旧执行者同时修改相同范围。

中止使用宿主真实取消或中断能力并核对结果；提交请求不代表终止。无法查询或取消时记录未知和遗留影响，不以删除记录或关闭界面冒充停止。用户介入、暂停和接管统一适用 PR-18。
