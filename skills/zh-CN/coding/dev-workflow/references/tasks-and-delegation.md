# 任务与按需委派

## 先设计任务

每项工作先说清：

| 内容 | 要回答的问题 |
| --- | --- |
| 目标 | 要解决什么，服务用户哪个目标？ |
| 输入 | 需要哪些事实、约定、资料或相关成果？ |
| 边界 | 范围、权限、不能改变的内容和允许写入位置是什么？ |
| 完成条件 | 交回什么成果，依据什么判断完成？ |

一个任务有一个清晰目标，可以包含连续操作。搜索、阅读和分析通常是同一调查过程，不按工具调用或步骤机械拆 Agent。

普通任务使用自包含消息，无需独立任务卡。除四项任务要素外，还提供相关原始要求、规模及来源、当前目标标识、已定选择与待决事项、有效前置成果及验收依据。只有后续程序确实需要解析时才约定结构化输出，不强制字数、章节数或 JSON。

派发适用 [progression.md](progression.md) PR-02、PR-03、PR-08；接回适用 PR-04 至 PR-07，更新按 PR-09 至 PR-11。具体推进条件以该文件为准，本文件说明如何准备消息和交接资料。

示例：

> 查明当前订单查询是否覆盖归档数据。阅读查询接口、实现及归档说明。只读，不修改文件。返回实际行为、关键依据、矛盾信息及仍需用户决定的问题。

## 何时委派

负责人、规划者、实现者、核验者均可发起委派，没有固定助理角色。子任务可独立交付、需要不同能力、具有独立检查价值或可有效并行时才拆分；几步即可完成的工作直接处理。

仅传相关目标、约束、事实与资料引用，不默认传全部历史。存在依赖就交代前置成果，不能假定对方自动知道其他任务输出。

## 将规则交给实际执行者

首次派发前读取本文件和 [roles.md](roles.md)，并让实际执行者取得以下包内资料，使用当前安装包的可访问路径；不能只传角色名。相同资料已经读取且未变化时可沿用。

| 任务承担者 | 必需资料及相关输入 |
| --- | --- |
| 规划者 | roles.md 的规划职责、[scale.md](scale.md)、[clarification.md](clarification.md)；原始目标、约束、参考资料及现状 |
| 实现者 | roles.md 的实现职责；有效方案、目标及验收依据、写入所有权、项目约定和已获授权的必需技能 |
| 核验者 | roles.md 的核验职责、[verification.md](verification.md)；原始目标、有效方案、当前成果、必要 diff 与已有证据，保留独立判断 |
| 需要接回、分流或进一步委派的执行者 | progression.md 中适用规则；再次派发前还需本文件及相应配置 |

资料不可访问时交代其适用约束或提供当前包中可访问的副本引用；仍无法获得必需输入时按 PR-02 处理。包内资料是本技能执行组成部分，不通过它调用其他手动技能。上下文继承不能代替确认任务消息包含必要输入。

## 接回成果

执行者交回实际成果位置、必要依据与未解决问题。规划者交方案、关键关系、验收方法和假设；实现者交实际改动、自检、方案偏差；核验者交检查方法、逐项结论、证据范围、遗漏及缺陷。事实、推断和用户待决事项分清。

委派者按完成条件核对后，明确接受或退回的范围、依据、剩余问题及责任方，在唯一记录同步后执行下一步。返回报告本身不是交接完成；部分可用成果只按明确范围使用。

委派者复核证据、处理矛盾、整合成果并承担责任，不能将本角色完整职责原样转包。进一步拆分交回委派者协调，避免递归转派失去整体把握。

## 配置与宿主能力

主角色派发应用 [roles.md](roles.md#执行配置) 与 [../assets/roles.json](../assets/roles.json) 的字段优先级；局部委派默认继承**直接委派者**，不是统一继承根线程，也不重复套用角色配置。配置与派发说明遵循 roles.md，委派者保留综合判断与最终责任。

派发前核对宿主真实工具 schema 和能力；只对具体值传覆盖参数，不把 `inherit` 当作模型名或思考档位提交。业务角色与宿主 `agent_type` 分开，避免宿主预设类型覆盖目标配置，不假设角色 ID 就是合法宿主类型。

继承配置和继承对话是两件事。优先使用宿主原生配置继承；需要显式传值时必须有可靠的直接委派者配置依据。按实际 schema 选择上下文方式，覆盖配置需要隔离上下文时传自包含任务消息；不能同时满足配置与上下文要求时说明限制，不猜参数或编造继承值，不因省略参数就断言继承成功。

指定模型或思考档位不支持、配置文件不可读或值无效时，报告具体问题并暂停受影响的派发，其他独立工作可以继续。已有用户授权的替代配置可直接使用并说明变化；否则不静默换模型、降档、忽略覆盖或转为主线程执行，不新增自动兼容数据库和重试链。

## 边界与结果

- 权限不能超过委派者；只读调查不借委派提前改实现。
- 写入明确文件所有权，保留用户和其他执行者修改；同一文件冲突时合并或串行处理。
- 核验执行者及参与核验的子任务不得参与被核验成果的实现；实现自检可作为依据，但不是独立审查。
- 并发、超时和重试按任务、风险及宿主限制设置必要停止条件，不预设所有任务统一人数或次数，不无边界重试。
- 子任务返回成果、必要依据和未解决问题；委派者检查是否满足完成条件，缺项反馈具体问题，不只拼接 PASS。
- 记录需要接回的真实执行者、结果位置、当前状态及配置依据。无法派发、调用失败或配置不受支持时如实说明，不制造虚假执行记录。
- 负责人代发时保留原任务发起者及配置差异，结果交原委派者整合；技术代发不增加逐项审批。
- 恢复或中止时核对仍在运行的任务和写入者，取消能力受限时披露遗留情况，不能只改文档状态就称全部停止。
