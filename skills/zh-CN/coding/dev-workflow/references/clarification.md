# 需求明确程度与用户决策

负责人及规划者开始规划、接回方案及发现重要需求变化时读取。先复用用户描述、已有回答、参考资料和明确委托，再判断是否存在影响实施的关键不确定性，不以完整方案文档作为需求清晰的前提。决定依据按 [progression.md](progression.md) PR-03 判断；方案就绪后的强制用户验收与实施放行统一按 PR-19 判断，两者不能互相替代。

## 判断是否需要讨论

| 当前情况 | 行动 |
| --- | --- |
| 用户已清晰描述目标、关键效果、范围或参考方案，足以规划 | 沿用描述，规划仅补充必要工程安排，不要求用户重新确认原话；当前方案就绪后仍按 PR-19 提交验收 |
| 只缺代码行为、环境条件或可查资料 | 先调查，由规划者处理已有授权内的技术细节，不把事实问题交用户 |
| 用户已明确委托相关设计选择 | 在委托范围内自行形成方案，说明主要选择，不逐项索取技术决定；整体方案仍按 PR-19 提交验收 |
| 存在会明显影响成果的目标歧义、偏好、业务行为或范围取舍，且用户未明确委托 | 先讨论相关决定，未解决前不实施依赖这些决定的部分 |
| 用户明确要求先讨论或先审阅方案 | 按要求展示具体内容并等待结论，不以通用执行授权越过该要求 |

没有完整技术方案不等于需求不清晰，也不能因为用户未指定每个颜色或参数就强制提问。区分可由工程判断补齐的细节与会改变用户期待的实质选择；完整参考方案、项目既有规范和用户明确委托均可提供决定依据。

可观察的交互失效、参数失配、明显穿模或验收条款冲突先由团队判断并处理，不因涉及观感就全部归为用户偏好。用户已委托的设计选择沿用委托；只有尚未委托、确实影响成果的实质取舍才提交用户决定。

## 规划者与负责人如何协作

规划者先区分用户已明确内容、查证事实、技术判断及需要用户决定的事项。存在关键待决事项时，返回足够讨论的初步方向、推荐理由、必要参照和具体问题；可以分析候选方案，但不能把未经决定的假设当成定稿，也不必先展开依赖这些假设的全部设计。

子 Agent 规划时由负责人组织用户讨论，将回答交回规划者继续深化；采用规划 thread 时，用户可直接与规划者讨论和调整，负责人接回相关消息与当前方案。方向讨论和方案验收可以合并，轮次由实际问题决定，不固定要求多套方案或逐项技术审批。已明确的内容不重复问；用户反馈或新事实改变关键前提时，只重新处理受影响部分。

Owner 的“内部审查通过”表示方案质量或可行性满足要求，不能代替用户对当前方案的认同。方案经 PR-05 检查就绪后，负责人必须主动通知并组织用户验收，展示具体方案、关键取舍及验收依据；不能仅落盘等待用户自行发现。用户可在主对话或规划 thread 中认可，经负责人按 PR-19 核对后推进，无需重复批准。

“我确认采纳”不能写成用户认可；任务开头的一般“开始做”不能冒充对随后方案的验收。多轮调整后用户说“可以了”，上下文明确指向当前方案且不存在待落实调整时可作为认同；“把这里改一下”只表示修订要求，不等于修订方案已获认可。

## 按需衔接 grilling

存在需要用户决定的关键不确定性时，可使用 `$grilling` 辅助讨论，实际技能名是 `grilling`，不使用 `grill-me`。它是可选的外部手动技能，不随本包安装，也不复制其正文或跨包读取其文件来绕过调用限制。

- 用户已同时显式指定，或在当前会话明确授权不清晰时使用 `grilling`，按依赖衔接，不重复索取授权。仅调用 `dev-workflow` 不等于授权调用其他手动技能。
- 未获调用授权时，负责人说明当前关键疑点并提示用户显式调用 `$grilling`；在获得授权前不读取或执行其正文。普通必要澄清仍可在当前对话进行，无需因可选技能暂停所有工作。
- 已授权但技能未安装或不可用时说明缺失；继续允许的调查与普通澄清，不假装已执行该技能，也不自行安装。
- 实际调用时遵循已安装 `grilling` 的规则，并提供已有决定、事实、相关授权及本次待澄清范围。其问答及共同理解确认针对该范围，不能重新打开无关或已经解决的决定。

## 实现前的决定依据

负责人向实现者交代采用的用户要求、参考依据、工程选择及当前方案的有效认同范围和核对依据。关键决定应能追溯到用户原始描述、明确反馈或相关自主决策委托；方案放行还必须具备 PR-19 依据，不能仅有内部审查结论。

通过 `grilling` 达成共同理解时，遵循该技能要求取得用户确认；共同理解确认只有明确覆盖当前具体方案时，才能同时作为 PR-19 的认同依据。所有规模的当前方案就绪后均须用户验收，轻量任务可用几句话说明做法和完成依据，不强制独立设计文档。已有同一方案的有效认同可复用，工程细节不逐项审批。

记录在现有 task.md 的目标、方案及待决问题中，区分用户已明确、工程判断、用户委托与待决定，保留当前方案引用、负责人验收通知、认同来源与范围，不建立新的批准文件或复制完整问答。等待期间可继续独立调查和明确用途的讨论草图，不能后台实施或派发未获认同的方案。实质方案变化按 PR-09、PR-19 重新验收受影响范围；已认可方案内的技术细节和实现纠偏无需重复验收。
