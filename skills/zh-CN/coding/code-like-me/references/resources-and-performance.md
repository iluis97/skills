# 资源与性能

## 资源生命周期

- 明确资源所有权、依赖方向、创建与释放责任，沿用项目生命周期管理方式。
- 正常结束、异常、提前返回及取消时，均保证本层拥有的资源得到正确释放。
- 借用或由容器管理的资源遵守其生命周期。

### 禁止项

- **越权关闭资源**：禁止擅自关闭借用或由容器管理的共享资源。
- **资源泄漏**：禁止在异常、提前返回或取消路径中遗漏本层拥有资源的释放。

## 性能取舍

- 先识别实际瓶颈，优先减少重复计算、无效查询、不必要的数据转换及可批量处理的访问。
- 性能目标可以授权结构性改造：算法、数据结构、数据布局、批量、缓存、并发或模块边界；范围限于测量确认的瓶颈路径及必要调用方，外部行为契约不变，除非任务明确授权。
- 大改按可验证单元推进，每一步只改变一个主要变量；前后在相同负载、数据和环境下对比，避免无法归因。
- 根据访问方式和数据规模选择数据结构；引入缓存、批量或并发时一并评估内存、事务及一致性代价。
- 测量前先写决策：明确指标、目标值和什么结果会改变当前做法；记录基线、运行次数和波动范围。
- 从实际运行、计数或剖析确认限制因素，能回答“为什么不能翻倍”；只读代码猜测不算证据。
- 排除测错对象：错误、缓存或跳过的工作、未执行的代码、未调优的一侧、噪声、过小的部分。
- 性能结论同时保留运行次数、波动范围和限制因素；没有基线或波动大于效应时，不声称提升或回归。

### 禁止项

- **无依据优化**：禁止在没有瓶颈证据时增加优化层次、微优化或改写结构；有测量证据的结构性改造不属此类。
- **无基线结论**：禁止在没有基线和波动范围时报告性能提升或回归。
- **把波动当效应**：禁止把小于测量波动的差异当成实际收益或回归。
- **测错对象**：禁止把错误、缓存命中、未执行代码或噪声当成优化效果。
