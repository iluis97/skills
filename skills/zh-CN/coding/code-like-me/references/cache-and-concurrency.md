# 缓存与并发

## 缓存一致性

- 重复且能够可靠失效的热点中间结果可以缓存，优先复用项目已有组件。
- 明确缓存键、生命周期、容量、写后失效及并发语义。
- 数据库写入后维护缓存时，优先复用提交后回调。
- 明确无事务场景和回调失败的处理方式；回调顺序本身不保证跨系统一致性，按业务需要保留既有重试、失效或补偿机制。

### 禁止项

- **缓存参数照搬**：禁止未经当前业务评估，直接采用其他业务的缓存容量或 TTL。
- **回滚后缓存残留**：禁止在数据库回滚后保留本次写入产生的缓存变化。
- **误信回调顺序**：禁止将提交后回调的执行顺序当成跨系统一致性保证。

## 并发与重复执行

- 并发实现同时考虑线程安全、业务状态、数据一致性和资源竞争。
- 检查状态可能在校验后变化的场景。
- 并发冲突优先消除共享状态、缩小共享范围或分离所有权，再考虑锁；锁不是默认首选。
- 按项目约定使用条件更新、锁或其他已有并发机制。
- 涉及重试、消息重投或重复请求时，明确幂等键、终态及副作用语义；仅在业务需要时沿用或补充幂等处理，不能幂等时说明重复执行的业务影响。

### 禁止项

- **依赖过期状态**：禁止在状态可能变化时，将此前读取或校验的结果当成后续写入的永久保证。
- **移除并发保障**：禁止将必要的并发和一致性检查当作重复判断删除。
