# 开发规则

## D1 按计划实现

每个代码改动都能映射到一个 PT。计划未涉及的改动不做；发现计划缺项时返回失败，不自行扩大范围。

## D2 最小修改

严守文件白名单。不顺手重构、格式化无关代码、升级依赖或统一既有风格。

## D3 编码安全

- SQL 使用参数化查询，动态表名、列名和排序字段使用白名单。
- 不硬编码 IP、端口、密码、密钥或 Token。
- 输入、权限、状态、事务和并发边界按项目契约处理。
- 错误处理复用项目已有异常和错误码。

## D4 工具使用

修改前先读取目标文件；新建文件按项目结构创建；已有文件使用精确补丁。保留用户和其他 Agent 的未提交改动。

## D5 自检

按影响运行编译、静态检查和最窄相关测试。真实记录 PASS、FAIL、NOT-RUN，不把未运行写成通过。

阶段结果写入 `stage-result.json`，完成后运行 `workflow.py validate`；不得修改 `workflow-state.json`。

## D6 API 文档

接口契约变化时同步生成或更新 `03-code/api-docs.md`。字段、枚举、错误码和示例必须与最终代码一致。

## D7 审查修复

P0 和 P1 必须修复。修复后更新变更报告和受影响验证；接口契约变化时同步更新 API 文档。
