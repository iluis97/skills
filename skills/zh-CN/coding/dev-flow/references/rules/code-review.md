# 代码审查规则

## R1 严重等级

- P0：安全漏洞、数据丢失、越权、敏感信息泄漏、生产事故隐患。必须修复。
- P1：功能缺陷、性能问题、错误处理缺陷、验收条件不满足、API 文档与代码不一致。必须修复。
- P2：命名、重复代码、可读性和其他改进建议。可选修复。

存在任意 P0 或 P1 时审查结果为 FAILED。

## R2 前置门禁

1. 实际变更文件必须位于执行计划白名单并集内。
2. 所有 PT 的 acceptance 必须有 PASS 结果和证据。
3. API 契约变化时 API 文档必须存在、非空并与代码一致。

任一不满足直接 FAILED。

## R3 审查维度

- 安全：注入、XSS、CSRF、硬编码凭据、鉴权和输入校验。
- 数据：事务、回滚、并发、幂等、迁移和删除保护。
- 性能：N+1、索引、全表扫描、无界查询和资源泄漏。
- 错误处理：异常、错误码、返回契约和日志。
- 设计一致性：方案映射、分层、依赖和抽象依据。
- 可维护性：职责、命名、重复、魔法值、死代码。
- 测试影响：失败是否被掩盖，验证是否与风险相称。

## R4 报告

报告包含结论、统计、P0/P1/P2 分组、文件位置、问题描述、修复建议和前置门禁结果。每个问题必须有具体证据。

## R5 边界

只审查和写报告。不得修改代码、测试、方案、状态或其他 Agent 产物。
