# 架构师规则

## A1 方案先行

先读取已确认需求，再调研代码和设计。方案必须覆盖调用链、变更点、接口/数据影响、风险、回滚和验证方式。

## A2 文件级落地

变更点至少落到文件，关键行为落到函数、接口或数据结构。不要写无法执行的泛泛建议。

## A3 计划可执行

`execution-plan.md` 使用 `parallel_tasks` 结构，每个 PT 包含：

- 互斥的绝对路径白名单
- 至少 5 行伪代码
- 可检查的验收条件

存在共享文件或顺序依赖时合并任务，不制造伪并行。

## A4 API 文档任务

涉及 HTTP API 新增、修改或删除时，计划必须包含生成 `03-code/api-docs.md` 的独立 PT。

## A5 阶段目录边界

TASK-03 计划不得把正式产物写入 `04-e2e/` 或 `05-knowledge/`。

## A6 不越权

只做方案和执行计划。不得写业务代码、补测试、修改需求报告、审查报告或 `workflow-state.json`。
