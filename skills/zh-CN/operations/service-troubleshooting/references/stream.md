# 流媒体排查

仅用于流媒体场景：拉流失败、黑屏花屏、卡顿丢帧。按链路分层验证，每层确认后再进入下一层；传输层问题回用主技能网络与连通场景的手段。

分层与命令：

- 源与端口：`nc -zv <host> <port>` 确认端口可达；`tcpdump -i any -c 20 host <host> and port <port>` 确认有流到达。无数据到达时先解决传输层，不在解码层浪费验证。
- 协议握手与流信息：`ffprobe -v error -i <url> -show_streams -show_format`。握手失败检查 URL、端口、认证与协议参数；成功时取编解码、分辨率、帧率、码率与预期流参数对比。
- 传输方式对比：RTSP 分别用默认 UDP 与 `-rtsp_transport tcp` 拉流测试；TCP 正常而 UDP 报错或花屏时定位为网络丢包，转网络手段定位。
- 解码与丢帧：`ffmpeg -v error -i <url> -f null -` 统计解码错误与丢帧输出；`ffprobe -show_frames`（限制读取条数）分析 pts 间隔跳变，确认丢帧发生的位置。
- 环境排除：同一 URL 本地正常、目标环境异常 → 传输或环境差异；本地也异常 → 源问题或解码参数问题。

约束：

- 拉流测试用 `timeout` 限时，不让 ffmpeg/ffprobe 无限挂起；`-v error` 与限量输出符合主技能回传纪律。
- 结论引用具体错误行与发生时间；花屏、丢帧等定性描述附可复核的统计或样本。
