# 网络与连通排查

仅用于网络与连通场景，或流媒体场景中确认传输层。按主技能的证据纪律执行。

按链路顺序验证，每步区分“不通”与“通但异常”：

- 名称解析：`getent hosts <域名>` 或 `nslookup`；解析失败先查 DNS 配置与记录，再查服务本身。
- 路由与丢包：`ping -c 4 <host>` 看通断；怀疑路径质量用 `mtr <host>` 看逐跳丢包与延迟。
- 端口连通：`nc -zv <host> <port>`；监听检查用 `ss -ltnp` 对照目标服务，确认监听地址与端口无误。
- 协议与应用层：`curl -v` 看握手、状态码与响应头；应用私有协议按其探测方式验证。

抓包：

- 用 `tcpdump -i any -c 20 host <host> and port <port>` 限制条数采集，控制回传量；需要留存时写入获准的文件并记录位置。
- 判定：SYN 无响应多为防火墙拦截或服务未监听；SYN 后收到 RST 多为端口未监听或主动拒绝；握手成功后数据停滞多为对端处理慢或中间设备断开，不是端口问题。

带宽：

- `iperf3 -c <host> -t 10` 测量可用带宽，与链路标称值和业务实际速率对比；测试限时执行，不让测量命令无限挂起。
- 丢包结论引用 `mtr`、`ethtool -S` 等可复核输出，不以单次卡顿推断丢包。
